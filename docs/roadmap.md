# 次の実験

## 1. 現行試作を測れるようにする

初期GUI、形式説明、正しさのテスト、合成画像の段階別ベンチマークを置く。ここまでを初期版とする。

## 2. 実機で静止画像を読む

対象端末を1台決める。96×96・白黒または4色を固定表示し、画像取得条件と復号成否を記録する。端末は未選定。最初から高密度・高速表示にはしない。

## 3. 位置と色を安定させる

四隅のマーカー、射影補正、色基準セル、ROI追跡を追加する。少量のファイルを実機で確実に復元できる状態を確認する。

## 4. 処理と撮影のボトルネックを測る

取得、補正、判定、ECC/CRCを分けて測定する。既知形式の固定、配列/Canvasの再利用、探索削減などを試す。ここでAndroidネイティブ受信、SIMD/GPUを必要に応じて選ぶ。

## 5. 格子以外を比較する

図形タイル、縞/位相、空間周波数のうち、小さな実装で比較できる候補を1つ選ぶ。方式ごとに全ファイル転送を作り直さず、ペイロード復元層を共通にする。合成劣化と実機画像で評価する。

## 6. 連続転送と欠落回復

時間方向の同期、タイル単位の回収、消失訂正、必要なら双方向制御を比較する。数MiBの原ファイルを継続して転送し、成功率・実効速度・発熱を報告する。

速度目標や独自形式の採用は測定後に決める。既存方式より優位とはまだ主張しない。
