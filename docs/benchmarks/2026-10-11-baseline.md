# 初期の検証記録

日付: 2026-10-11（Asia/Tokyo）

## 正しさ

移植後に `npm test` 相当の `node prototypes/browser/test.cjs` を実行し、正常終了した。

- 256種類のバイトすべてで13通りの単一ビット誤りを訂正し、78通りの二重ビット誤りを拒否。
- 9設定すべてで最大ペイロードの画像往復と一致を確認。
- 画像に余白と位置ずれを追加し、外枠検出から復号して一致。
- ヘッダーの単一ビット誤りを訂正して一致。
- 2 MiBのランダムデータを256×256・16色の105フレームに分割し、逆順に画像から復元して完全一致。

移植元のブラウザGUIでも128 KiBのデモを24フレームのCanvas画像から復元し、SHA-256一致を確認している。これは同一ブラウザ内の自己テスト。別端末・カメラ・実際の画面共有経路による転送成功の証拠ではない。

## 合成画像での処理時間

実行: `node scripts/benchmark-codec.cjs --output docs/benchmarks/2026-10-11-synthetic.json`

Node.js v24.12.0、Windows x64、Intel Core i7-4790。1セル3×3画素の劣化なし画像。ウォームアップ2回、各処理7回の測定。取得画像の生成や検証assertはタイマーの外。正しさのテスト完了後、単独のベンチマーク実行で記録した。OS上の他プロセスやCPU周波数は制御していない。

| 格子 | 色数 | 自動復号p50 | 既知形式の色判定p50 | 既知セルのECC/CRC等p50 |
|---|---:|---:|---:|---:|
| 96×96 | 2 | 1.32 ms | 0.70 ms | 0.25 ms |
| 96×96 | 4 | 2.23 ms | 1.05 ms | 0.51 ms |
| 96×96 | 16 | 3.78 ms | 1.55 ms | 0.39 ms |
| 192×192 | 2 | 6.90 ms | 2.24 ms | 0.42 ms |
| 192×192 | 4 | 10.84 ms | 3.02 ms | 0.97 ms |
| 192×192 | 16 | 18.85 ms | 6.37 ms | 2.46 ms |

| 256×256 | 4 | 28.71 ms | 5.30 ms | 1.54 ms |

[JSONの測定結果](2026-10-11-synthetic.json) に外枠検索、p95、画像サイズなども記録した。個別処理と自動復号は独立に測定しているため、表の値は単純加算しない。

この実装・環境では、既知セルのECC/CRC等より色判定のほうが時間を使っている。また自動復号は既知形式の処理より重く、形式候補探索を削減する余地がある。ただしウォームアップ、実行順序、JIT、配列確保の影響があり、他方式の優劣や端末性能の上限は示していない。

画像入力だけのベンチマークなので、カメラの取得速度・撮影後の成功率・実効ファイル転送速度は未測定。GPU、Android、圧縮、消失訂正を含めた評価でもない。
